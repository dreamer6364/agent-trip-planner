# Agent 智能行程规划系统 - 产品需求文档 (PRD)

## 1. 项目概述

### 1.1 产品愿景
构建一个基于 AI Agent 的智能行程规划系统，用户通过自然语言描述出行需求，系统自动生成包含时间安排、路线规划、地图导航的完整行程方案。

### 1.2 核心价值
- **自然语言交互**：无需填写复杂表单，像和导游聊天一样规划行程
- **智能优化**：自动处理时间冲突、路线优化、优先级排序
- **异步生成**：后台异步规划，不阻塞用户界面
- **可迭代优化**：支持基于反馈的多轮重新规划

---

## 2. 用户角色

| 角色 | 权限 | 说明 |
|------|------|------|
| 游客 | 临时生成、查看、导出行程 | 不登录可用，数据本地存储或临时会话 |
| 登录用户 | 全部功能 + 历史保存/同步/分享 | 账户体系，云端持久化 |

## 3. 核心功能需求

### 3.1 行程输入模块 (FR-01 ~ FR-05)

#### FR-01 自由文本输入
- **输入框**：支持多行文本，placeholder 示例："计划周末两天去杭州，想去西湖、灵隐寺、河坊街，早餐吃包子，午餐尝尝杭帮菜..."
- **解析能力**：
  - 地点识别（POI 名称、地址、别名）
  - 活动类型识别（游玩、就餐、住宿、购物、交通、休息）
  - 时间偏好提取（"早上"、"中午"、"晚上"、"大概 2 小时"）
  - 约束条件（"必去"、"如果有时间"、"不想太赶"）

#### FR-02 时间范围设定
- **整体时间**：开始日期时间、结束日期时间（精确到分钟）
- **快捷选项**："今天"、"明天"、"本周末"、"下周三" 等自然语言解析
- **时区处理**：自动识别目标城市时区，支持跨时区行程

#### FR-03 交通方式选择
| 方式 | 适用场景 | 速度系数 | 备注 |
|------|----------|----------|------|
| 步行 | 短距离（<3km）、景区内部 | 1.0x | 默认 |
| 公共交通 | 城市内中长距离 | 1.2x | 地铁/公交/打车混合 |
| 自驾 | 郊区、多景点分散、家庭出行 | 0.9x | 需考虑停车时间 |
| 骑行/共享单车 | 短中距离、风景线路 | 1.1x | 可选 |

- 支持**分段指定**（如：市内打车，景区步行）
- 支持**避峰设置**（避开早晚高峰）

#### FR-04 地点优先级标记
- **必去地点** ⭐：硬性约束，必须安排进行程
- **推荐地点** 🟢：时间允许时安排
- **可选地点** ⚪：有富余时间时安排
- **不想去** 🚫：明确排除

> 交互：列表项右侧下拉/图标切换，或在文本中用符号标记（如 `⭐西湖` `⚪博物馆`）

#### FR-05 个人偏好配置
| 偏好项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| 景点游玩时长 | 单选/自定义 | 2h | 可按景点类型差异化（博物馆 3h、公园 1.5h） |
| 就餐预留时长 | 单选/自定义 | 1.5h | 早/中/晚餐可分别设置 |
| 起床/就寝时间 | 时间选择器 | 08:00 / 23:00 | 定义可安排活动窗口 |
| 午休/避开时段 | 多时段 | 13:00-14:00 | 不可安排活动的时间段 |
| 单日最大行程强度 | 滑块 | 中等 | 轻松/标准/紧凑，影响并行活动数与缓冲时间 |
| 餐饮偏好 | 多选标签 | - | 本地特色/快餐/素食/清真/避过敏原 |
| 无障碍需求 | 开关 | 关 | 优先无障碍路线、电梯、坡道 |

### 3.2 智能规划引擎 (FR-06 ~ FR-08)

#### FR-06 异步规划任务
- **提交即返回**：用户点击"生成行程"后立即返回任务 ID，页面轮询/WebSocket 推送进度
- **进度阶段**：解析输入 → 地理编码 → 约束建模 → 求解优化 → 路线生成 → 结果渲染
- **超时处理**：超过 60s 未完成，允许用户选择"继续等待"或"稍后查看结果"

#### FR-07 规划算法核心逻辑
**输入**：地点集合 L、时间窗 [T_start, T_end]、交通方式 M、偏好配置 P、优先级权重 W

**约束建模**：
```
变量：x_i ∈ {0,1} (地点 i 是否安排)
      t_i_start, t_i_end (地点 i 的开始/结束时间)
      route_{i,j} (i→j 的路径与耗时)

约束：
1. 时间窗约束：T_start ≤ t_i_start < t_i_end ≤ T_end
2. 时长约束：t_i_end - t_i_start ≥ duration_i(P)
3. 交通约束：t_j_start ≥ t_i_end + travel_time(i,j,M)
4. 优先级约束：必去地点 x_i = 1
5. 互斥约束：同一时段仅能在一个地点
6. 避开时段：t_i ∉ blocked_periods(P)
```

**目标函数（加权求和）**：
```
Maximize: Σ W_priority(i) * x_i                    // 覆盖高优先级地点
        - α * Σ travel_time(i,j)                   // 最小化路途时间
        - β * Σ |t_i_start - preferred_time_i|     // 贴合偏好时间
        - γ * fragmentation_penalty                // 减少碎片化空窗
```

**求解策略**：
- 小规模（<15 个地点）：OR-Tools CP-SAT 精确求解
- 大规模：遗传算法/模拟退火 + 启发式插入
- 实时性要求：< 10s 返回可行解，< 30s 返回近优解

#### FR-08 冲突处理与降级规则
当**全部必去地点无法在时间窗内完成**时，按以下规则处理：

| 规则优先级 | 处理动作 | 用户提示 |
|------------|----------|----------|
| 1 | 压缩可选/推荐地点时长至最小值 | "已压缩可选地点游玩时间" |
| 2 | 移除最低优先级可选地点 | "为安排必去地点，已移除 [地点名]" |
| 3 | 延长行程结束时间（≤ 2h） | "建议将结束时间延至 [时间]，可完整安排" |
| 4 | 建议拆分为多日行程 | "行程过满，建议拆分为 2 天" |
| 5 | 标记冲突地点，输出"部分可行"方案 | "⚠️ 以下地点无法安排：[列表]，已生成可行部分" |

> 所有降级动作需在结果中**显式标注**，用户可一键撤销/调整。

### 3.3 结果展示与交互 (FR-07, FR-09, FR-12)

#### FR-09 行程方案展示
**时间轴视图（主视图）**：
```
08:00  出发 🏠 → 🚌 地铁 25min
08:30  ⭐西湖漫步 (2.5h)  [预留拍照 30min]
11:00  🍽 午餐：楼外楼 (1.5h)  [推荐：西湖醋鱼]
12:30  🚌 公交 20min
13:00  🟢灵隐寺 (2h)  [备选：法喜寺]
15:00  ☕ 休息/咖啡 (45min)
15:45  ⚪河坊街逛吃 (1.5h)  [可选]
17:15  🚌 返程
```
- 每行可展开：地图预览、详情、替代方案、编辑按钮
- 冲突/降级项用 ⚠️ 高亮，点击查看处理原因

**地图路线视图**：
- 地图渲染路线、分段交通方式图标
- 点击站点跳转时间轴对应行

**统计卡片**：
- 总耗时、在途时间、游玩时间、就餐时间、空闲时间
- 覆盖必去/推荐/可选地点数量
- 预估花费（餐饮+门票+交通）

#### FR-10 自然语言反馈重规划
- **输入框**："我想把午餐改成素食"、"西湖想多待 1 小时"、"不要去河坊街了"、"换成自驾"、"把开始时间推迟半小时"
- **解析 → 增量更新**：不完全重算，仅调整受影响片段
- **版本历史**：保留每轮规划结果，支持回滚对比

#### FR-11 模糊/无法解析地点处理
| 情况 | 识别方式 | 处理策略 |
|------|----------|----------|
| 别名/口语名 | 别名库 + LLM 归一化 | 自动映射标准 POI，标注"已识别为：XXX" |
| 同名地点 | 结合城市/区域上下文 | 弹窗让用户确认（含地图预览） |
| 无法定位 | 地理编码失败 | 标红标记，建议用户补充地址/经纬度/关键词 |
| 关闭/不存在 | POI 状态 API | 提示"该地点可能已关闭/不存在"，推荐替代 |

## 4. 非功能性需求 (NFR)

| 维度 | 指标 |
|------|------|
| **响应时间** | 提交→任务创建 < 500ms；规划完成推送 < 30s（P95） |
| **并发** | 支持 1000+ 并发规划任务（异步队列 + 水平扩展） |
| **可用性** | 99.9% SLA，多区域部署 |
| **数据一致性** | 行程版本乐观锁，冲突自动合并提示 |
| **隐私合规** | GDPR/个保法合规，位置数据本地加密，最小化采集 |
| **无障碍** | WCAG 2.1 AA，键盘全程可操作，屏幕阅读器友好 |
| **浏览器支持** | Chrome/Edge/Safari/Firefox 最近 2 个主版本，移动端自适应 |

## 5. 数据模型核心实体 (Conceptual)

```typescript
// 行程主表
interface Trip {
  id: string;
  userId?: string;           // null = 游客
  title: string;
  rawInput: string;          // 原始自由文本
  parsedInput: ParsedInput;  // 结构化解析结果
  timeRange: { start: Date; end: Date };
  transportMode: TransportMode;
  preferences: UserPreferences;
  status: 'draft' | 'planning' | 'completed' | 'failed' | 'archived';
  currentVersionId: string;
  createdAt: Date;
  updatedAt: Date;
}

// 行程版本（每次规划/编辑生成新版本）
interface TripVersion {
  id: string;
  tripId: string;
  version: number;
  parentVersionId?: string;  // 回溯链
  activities: Activity[];
  routes: RouteSegment[];
  conflicts: Conflict[];
  stats: TripStats;
  createdAt: Date;
  feedback?: string;         // 触发本版本的用户反馈
}

// 单个活动项
interface Activity {
  id: string;
  poi: POI;                  // 关联地点详情
  type: 'visit' | 'meal' | 'stay' | 'transit' | 'buffer';
  priority: 'must' | 'recommended' | 'optional';
  timeWindow: { earliest: Date; latest: Date };  // 硬约束
  scheduledTime?: { start: Date; end: Date };    // 求解结果
  duration: { min: number; preferred: number; max: number }; // 分钟
  status: 'scheduled' | 'removed' | 'conflict';
  notes?: string;
}

// 路线片段
interface RouteSegment {
  from: ActivityId | 'origin';
  to: ActivityId | 'destination';
  mode: TransportMode;
  polyline: GeoJSON.LineString;
  distance: number;      // 米
  duration: number;      // 秒
  cost?: number;         // 预估费用(元)
}

// 用户偏好
interface UserPreferences {
  visitDuration: Record<POICategory, number>;  // 分钟
  mealDuration: { breakfast: number; lunch: number; dinner: number };
  activeWindow: { start: string; end: string }; // "08:00"-"23:00"
  blockedPeriods: { start: string; end: string }[];
  intensity: 'relaxed' | 'standard' | 'packed';
  dietaryTags: string[];
  accessibility: boolean;
}
```

## 6. 里程碑与交付计划

| 阶段 | 周期 | 核心交付 | 验收标准 |
|------|------|----------|----------|
| **M0 基础设施** | 1-2 周 | 项目初始化、CI/CD、数据库、认证、基础 UI 框架 | 登录/注册/空白页可跑通 |
| **M1 核心解析与规划** | 3-4 周 | 文本解析、地理编码、约束建模、CP-SAT 求解、基础结果展示 | 10 个地点以内规划 < 5s，结果可视化 |
| **M2 交互与地图** | 2-3 周 | 时间轴编辑、地图路线、反馈重规划、冲突降级提示 | 端到端流程通顺，支持 3 轮反馈迭代 |
| **M3 多模态与优化** | 2-3 周 | 多交通方式、大规模启发式求解、偏好学习、导出分享 | 20+ 地点规划 < 15s，导出格式完整 |
| **M4 用户体系与历史** | 1-2 周 | 账户、历史、同步、模板、协作分享 | 登录用户全功能可用 |
| **M5 观测与上线** | 1 周 | 监控告警、压测、文档、部署、灰度发布 | SLA 达标，回滚预案就绪 |

## 7. 风险与对策

| 风险 | 等级 | 对策 |
|------|------|------|
| LLM 解析不准导致规划偏差 | 高 | 增加人工确认步骤、置信度阈值、结构化校验、用户可编辑解析结果 |
| 组合爆炸导致求解超时 | 高 | 分层求解（精确+启发式）、时间切片、增量求解、缓存常见模式 |
| 地图/路线 API 成本/限流 | 中 | 多厂商降级、路线缓存、批量请求合并 |
| 用户偏好千差万别难建模 | 中 | 显式偏好配置 + 隐式学习（历史行程反推）、可解释的权重面板 |
| 移动端地图交互体验差 | 中 | 专门的移动端布局、手势优化、离线包预加载 |
